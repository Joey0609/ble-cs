On the established link: connection events, then encryption

Connection interval anchor to anchor, one event each
Channel map the data channel of each event
Peripheral latency events the Peripheral may skip
Supervision timeout silence before the link is lost
Event budget reserved per event, not negotiated
Encryption key from pairing, switched on by the LL
Core 6.0 · Vol 6, Part B (Link Layer)

The parameters from CONNECT_IND turn the link into a fixed rhythm. The Central sends its first packet inside the transmit window; that packet sets the first anchor point. From then on a connection event starts at every anchor, one connection interval apart, and the event counter goes up by one each time. In each event the Central transmits first and the Peripheral replies a fixed inter-frame space later; if either side has more data they keep alternating, as in event n+1. Each event uses one data channel, chosen from the channel map by the hopping algorithm. The event budget is how long a controller reserves for an event; it is a local scheduling choice, not negotiated, and an event with little data ends early. The rest of the interval is free for other radio activity, and that is where Channel Sounding will go. Peripheral latency lets the Peripheral skip events when it has nothing to send, as in event n+3, without moving the anchors. The supervision timeout ends the link if no valid packet arrives for that long. These events also carry the link's own control traffic, and the first thing that matters for CS is security. If the devices are not bonded yet, they pair through the Security Manager, which runs over the link like any other data. The Central then starts Link Layer encryption with LL_ENC_REQ and LL_ENC_RSP, followed by LL_START_ENC_REQ and LL_START_ENC_RSP, using the key from pairing or from an earlier bond. From then on every packet on the link is encrypted, and only then may CS security start: Channel Sounding needs this encrypted link. The figure is illustrative; the channel numbers are examples.

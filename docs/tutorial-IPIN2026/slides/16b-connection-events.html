连接间隔 相邻时间锚点之间的间隔，每个锚点对应一个事件
信道映射 每个事件的数据信道
外围设备延迟 外围设备可能跳过的事件
连接监视超时 无有效数据包的最长允许时长
事件时间预算 控制器为每个事件预留的时间，不经双方协商
Encryption 使用配对密钥，由链路层启用
Core 6.0·第 6 卷，B 部分（链路层）

CONNECT_IND 中的参数将链接变成固定节奏。中心设备在传输窗口内发送其第一个数据包；该数据包设置了第一个锚点。从此每个基站开始一次连接事件，间隔一个连接距离，事件计数器每次加一。在每种情况下，中心设备先发送，外围设备随后回复固定的帧间间隔；如果任何一方有更多数据，它们就会保持交替，如事件 n+1 所示。每个事件使用一个数据信道，该数据信道是通过跳频算法从信道映射中选择的。事件预算是控制器为事件预留的时间；这是本地调度选择，未经协商，数据很少的事件会提前结束。剩余的时间间隔可用于其他无线设备活动，这就是信道探测将进行的地方。 外围设备延迟允许外围设备在没有要发送的内容时跳过事件（如事件 n+3 中），而无需移动基站。如果在这么长的时间内没有有效的数据包到达，则监督超时会结束链接。这些事件还携带链路自身的控制流量，对于CS来说，首先重要的是安全性。如果设备尚未绑定，它们将通过安全管理器进行配对，安全管理器像任何其他数据一样在链路上运行。然后，中心设备使用来自配对或先前绑定的密钥，开始使用 LL_ENC_REQ 和 LL_ENC_RSP 进行序列层加密，然后是 LL_START_ENC_REQ 和 LL_START_ENC_RSP。从此链路上的每个数据包都被加密，CS安全才开始：探测需要这个加密链路。该图是说明性的；信道号是示例。

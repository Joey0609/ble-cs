Core · Vol 6, Part B, §5.1.23–5.1.26 (CS LL procedures)

CS setup needs no new link: it is a series of Link Layer control procedures, and their PDUs travel in ordinary connection events of the encrypted ACL link from the previous slide. The capabilities exchange tells each side what the other supports. The configuration procedure fixes a CS configuration, identified by a Config_ID: the step modes, the channel map, and which device is initiator and which is reflector. The CS Security Start procedure is sent by the Central and exchanges the seeds for the CS random bit generator, which later chooses the channel order and the random bits in every step; it may only run after Link Layer encryption. Then the CS Start procedure sets the timing. Either side may send LL_CS_REQ with a proposal; a Peripheral answers with LL_CS_RSP, and the Central always closes with LL_CS_IND. LL_CS_IND names a connection event, connEventCount, and the first CS procedure starts at an offset after that event's anchor, inside the connection interval. Procedures then repeat every procedure interval, counted in connection intervals, for the procedure count or until stopped. The ACL events keep running in between and carry the results.

RAS：传送并匹配反射端结果

  1. 发现并配置客户端读取 RAS 特征并订阅所选的数据/控制特征。
  2. 实时或按需完成后传输结果，或通过控制点获取存储的测距过程。
  3. 分割并重新组装使用ACL中CS留下的空口占​​用时间中的ATT通知/指示；检测间隙并重新组装测距过程。
  4. 配对和估计将测距过程、步骤、信道和天线路径与发起端的本地结果匹配，然后组合：\( H[k] = \mathrm{PCT}_I[k]\,\mathrm{PCT}_R[k] \) (18c)。
典型的路由是反射端 = RAS Server，发起端 = RAS Client。即使 CS 成功运行，缺少远端数据也意味着配对测量不完整。
RAS 1.0·§2.7； §3.1–3.5

这些服务角色独立于中心设备/外围设备。 RAS 报告控制器产生的测量结果，包括测距过程/子事件上下文、步骤数据和状态。获得完整的子事件结果或完整的测距过程结果后开始实时交付；仍受ACL调度。这些段与偏离其基站的 CS 事件共享连接：如果测距过程间隔留下的 ACL 空口占用时间太少，则通知备份和结果会延迟到达或丢失。该项目将该案例报告给主机 RAS_DATA_LOST。按需操作使用存储的数据和 RAS 控制点；缓冲区覆盖和可选的丢失段检索很重要。阅读功能支持，而不是假设所有恢复操作都存在。在解释记录之前重新组装，匹配测距过程身份和步骤，并处理计数器换行和不完整/中止的结果。基线PBR一次配对一个单音信号：相同的测距过程（测距计数器和配置）、相同的步骤、相同的信道和相同的天线路径；然后两个 PCT 才会相乘。该项目根据步骤在测距过程中的位置对步骤进行配对，并将模式或信道不同的步骤视为不匹配，将其排除在外。幻灯片 26d 介绍了数据包大小和 ATT MTU。测距算法仍然是一种实现选择。

来源： RAS 1.0·§2.7； §3.1–3.5.

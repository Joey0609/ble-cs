调度幻灯片展示了如何步骤填充子事件，子事件形成CS事件以及CS事件形成测距过程。以下是实施者选择的四种设置，以及每种设置的成本，用于通过该堆栈使用的基准工作负载：模式 2 下的 72 个信道，一个天线路径，以及上一张幻灯片的 nRF54 步骤时序。

每个子事件都会以一到三个模式 0步开始。他们估计两个无线设备之间的频率偏移，随后的相位测量取决于频率偏移。根据我们的计时，每个子事件花费 278 µs（包括其重新调整间隙），并且在每个子事件中都会再次支付：72 个信道的一个子事件需要 10.2、10.4 或 10.7 ms，其中有一个、两个或三个模式 0 步骤。

更多的子事件适合更小的窗口：72 个信道以 7.5 ms 的间隔需要两个。每个子事件都会重复 mode-0 步骤并添加 RAS 子事件标头，最后一个不适合的步骤会留下未使用的尾部时间。分成短短的2.8毫秒子事件，相同的信道需要五个子事件，十个模式0步骤和12.4毫秒的步骤，超过两个CS事件。 子事件间隔以 625 µs 为单位，比子事件加 150 µs 更长，在 CS 事件内留下间隙：两个 5.5 ms 的子事件相隔 6.25 ms，在 11.7 ms 上保持 10.9 ms 的步骤。 整个 ACL 间隔中的测距过程间距为 RAS 和其他链路提供了空间并设置了速率。分割测距过程不会进行新的测量：信道数组和模式序列在子事件和事件中继续。

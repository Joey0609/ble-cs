Core · Vol 6, Part B, §4.5.18 (CS procedures and subevents)

Zoom into the CS box of the previous slide. What we drew there is a CS subevent, the block of time in which the two radios run CS steps. Subevents are grouped into CS events, and CS events into a CS procedure, one ranging measurement. The anchoring rule answers the obvious question: each CS event is tied to one ACL anchor, and its first subevent starts the offset after that anchor. The other subevents of the same event are not tied to anchors; each starts one subevent interval after the start of the previous one. The next CS event starts at another ACL anchor, one event interval later, so a procedure with several events spans several ACL anchors, as here with two events of two subevents each. Procedures repeat one procedure interval apart, counted in connection intervals. The specification allows up to 32 subevents in a procedure, and events and subevents may even run past the connection interval. What happens inside a subevent, its steps, is the next slide. The timeline is illustrative; the simplest setup is one event with one subevent, which is the box on the previous slide. The ACL events keep running at every anchor.

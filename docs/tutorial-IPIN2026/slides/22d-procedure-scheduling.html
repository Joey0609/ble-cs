The top level: a CS procedure is one ranging measurement, and it ends by channel coverage, not by a step count. Each procedure shuffles the enabled channels into an array for the non-mode-0 steps and works through it Channel_Map_Repetition times; when the last pass is used up, the procedure is complete, whether that took one subevent or several CS events. It is cut short if Max_Procedure_Len, counted in 625 µs, runs out first, or when it reaches 256 steps; the result then covers fewer channels. The next procedure starts one procedure interval after the start of this one, counted in connection intervals, so this one has to end before that; Procedure_Count sets how many run, 0 until stopped. Each procedure starts from a fresh draw of the random generator: a new channel order and new main-mode counts, and its first subevent has no steps to repeat.

This is where the parameters meet. The firmware's default request is 36 channels with one map repetition, but a Max_Procedure_Len of 10 × 625 µs, room for a single 6 ms subevent; the planner therefore predicts procedures that end by length after one subevent, having measured only part of the 36 channels. The planner's schedule view names the condition that ended each procedure. The rate follows from the procedure interval: one result every procedure interval × connection interval, the arithmetic on the ACL timing slide.

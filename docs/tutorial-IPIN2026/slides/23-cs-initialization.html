CS procedure initialization

The ACL link carries setup; the controllers then execute the agreed CS schedule.

  1. CapabilitiesFind the shared roles, modes, radio options, antenna limits and supported step timings.
  2. Reflector calibrationUse zero frequency actuation error (FAE), a known table, or retrieve the table when required.
  3. ConfigurationAgree a configuration identifier (Config_ID), measurement modes, sequence rules, channels and step timing.
  4. CS securityExchange seed material over the encrypted data link and initialize the shared random generator.
  5. Procedure startAgree the schedule; the Central sends the final start parameters.
Before the first step: configuration and FAE known, CS security ready, start timing agreed.
Core 6.0 · Vol 6, Part B, §5.1.23–29

This is a dependency overview, not a mandatory total ordering of every setup operation. Capabilities must be known before configuration; CS Security Start requires an encrypted ACL. The initiator needs the reflector FAE information before CS starts. Setup exchanges need not repeat before every procedure: an accepted configuration and known capabilities can be reused, and repeated procedures advance the DRBG state. Central/Peripheral are ACL roles; Initiator/Reflector are selected per CS configuration. Either device can request CS start; the Central supplies the final indication. Read controller completion events rather than treating a successful host command submission as completed negotiation.

Sources: Core 6.0 · Vol 6, Part B, §5.1.23–29.

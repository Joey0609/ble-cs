From advertising to the first CS procedure

CS has no link of its own: all setup and every reflector result travel over the encrypted LE ACL link.

Central/Peripheral are link roles and independent of the CS roles; this project pairs Central with CS initiator.

ACL means the LE asynchronous connection-oriented logical transport: BLE's connected, bidirectional path for Link Layer control and user data. Channel Sounding reuses it for everything except the CS steps themselves. Connect. The Peripheral advertises connectably. The Central answers with CONNECT_IND on legacy advertising or AUX_CONNECT_REQ on extended advertising. That PDU fixes the initial access address, connection interval, peripheral latency, supervision timeout and channel map; a connection parameter update can change timing later. Here the initiator calls bt_conn_le_create with the interval from the applied CS configuration and automatic GAP parameter updates are disabled. Secure and prepare GATT. The data length update (LL_LENGTH_REQ/RSP) and the ATT Exchange MTU run automatically after the connection. The initiator then calls bt_conn_set_security; pairing through SMP is followed by the Link Layer encryption start. CS security needs an encrypted link but no stored bond in the hostless route. When reflector data is requested through RAS, the initiator discovers the Ranging Service (bt_gatt_dm_start), reads its features and subscribes to real-time ranging data. CS setup is a sequence of LL control procedures, each triggered by an HCI command from the initiator host: read remote capabilities (bt_le_cs_read_remote_supported_capabilities, LL_CS_CAPABILITIES_REQ/RSP), create the configuration (bt_le_cs_create_config, LL_CS_CONFIG_REQ/RSP), start CS security (bt_le_cs_security_enable, LL_CS_SEC_REQ/RSP, which exchanges the material for the CS DRBG), and enable procedures (bt_le_cs_procedure_enable, LL_CS_REQ/RSP/IND). LL_CS_REQ carries the connection event counter where CS starts and the allowed offset from the ACL anchor; the next slide shows that timing. Ranging. Procedures then repeat on the ACL schedule and the reflector returns its step data as RAS notifications, again over the ACL link. Roles: a Central can be CS initiator or reflector, and so can a Peripheral. In the main hosted route and the hostless initiator of this repository, the Central is the CS initiator and RAS client. Sources: Bluetooth Core Specification 6.2, Vol 6 Part B, Sections 4.5 (Connection state) and 5.1 (Link Layer control procedures, including the Channel Sounding procedures); Bluetooth LE Primer, Section 7.8.1 (LE ACL); repository: common/libs/cs_roles/cs_role_link.c and cs_role_initiator.c, cs_hostless_initiator/prj.conf.

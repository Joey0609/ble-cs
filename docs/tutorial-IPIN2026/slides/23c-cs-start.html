启动测距过程：确定最终时序

  1. LL_CS_REQ任一对等方提出 Config_ID 和允许的启动/调度参数。
  2. LL_CS_RSP当中心设备请求时，外围设备返回可接受的响应。
  3. LL_CS_IND中心设备最终确定调度，也在外围设备发起请求时确定。
启动时间锚点在测距过程中跨测距过程
connEventCount
+ ACL 后的偏移量 时间锚点		子事件长度/间隔/计数
CS事件间隔；持续时间限制		测距过程间隔和计数
0 次：重复直到停止
双方都根据配置与共享随机数发生器在本地生成步骤；不传送每个步骤的时间表。
核心 6.0·第 6 卷，B 部分，§5.1.26

对于中心设备发起的启动，顺序是请求、响应、指示。对于外围设备发起的启动，中心设备可以用最终指示进行应答。拒绝也是可能的。 connEventCount 和偏移建立共同的启动时刻； CS事件和测距过程间隔采用ACL连接间隔，子事件间隔采用625微秒单位。在此阶段，配置参数并未全部重新协商。正常的 ACL 活动继续受调度约束；因此，控制和结果流量需要与CS一起的空口占用时间。测距过程开始完成报告实际选择的值。

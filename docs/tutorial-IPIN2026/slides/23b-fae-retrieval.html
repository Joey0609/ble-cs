Frequency actuation error (FAE) retrieval

Check the reflector’s No_FAE (“no frequency actuation error”) capability before requesting its table.

ConditionInitiator action
No_FAE = 1FAE is zero on every permitted CS channel. Do not send LL_CS_FAE_REQ.
No_FAE = 0
table known		Supply the known reflector table to the controller; no new air exchange is needed.
No_FAE = 0
table unknown		Request LL_CS_FAE_REQ → receive LL_CS_FAE_RSP before starting CS.
The 72-entry table describes the reflector’s per-channel actuation error. Mode 0 still measures the changing frequency offset in every subevent.
Core 6.0 · Vol 6, Part B, §5.1.29; §2.4.2.52

The request is conditional on No_FAE being zero and the table not already being known. The specification prohibits requesting a table from a peer that declares No_FAE = 1. A potential initiator requests the table of its potential reflector, independently of their Central/Peripheral roles. If CS roles reverse, use the new reflector’s information. The table is calibration information, not a value negotiated to a compromise. It must be known before the procedure; it is not retrieved in every subevent. Each subevent’s mode-0 measurement still supplies the current relative frequency estimate. Manage cached information for the correct peer and calibration.

Sources: Core 6.0 · Vol 6, Part B, §5.1.29; §2.4.2.52.

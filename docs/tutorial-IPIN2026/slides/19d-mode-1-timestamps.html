这页说明 CS 如何把往返测时落实为报告值。发起端发送 CS_SYNC，反射端在一个传播时间后收到，经过周转间隔再回复 CS_SYNC；回复再经过一个传播时间到达发起端。双方在天线端口定义发出与到达时间戳，并扣除已知内部延迟。到达时刻不是简单检测边沿，而是把接收包与预期接入地址、以及可选序列做相关，取相关峰对应的延迟。发起端测 A = ToA − ToD，反射端测 B = ToD − ToA，各间隔只使用一台设备的时钟，因此未知时钟初始偏移不进入式子。A − B 是往返传播时间。

发起端还用模式 0 的相对频偏 FFO 校正时钟速率差，因此式中除以 1 + FFO·10⁻⁶。该校正由发起端控制器在上报前完成，反射端不应重复执行；主机只需对两份报告做相减，这也是当前应用的处理。双方并不上报原始时间戳，而是上报测得间隔扣除已知标称部分（包时长与收发间隔）后的有符号值，单位为 0.5 ns。报告分辨单位不等于测量精度。

RTT 类型决定相关对象：只用接入地址、加入探测序列，或使用随机序列。交替 1/0 的探测序列让高斯频移键控频率尽可能快地变化，增大有效带宽，改善定时并产生相位信息；因为序列周期性重复，应先以接入地址锁定，再以序列细化。随机序列更难伪造，并配有归一化攻击检测指标 NADM。使用时间差前先检查包质量。图为示意；这种包交换对应后续的模式 1，其真实时长见模式时序图。

建立连接：广播、连接与参数协商

由 CONNECT_IND 确定
  • 连接间隔、外围设备延迟、连接监视超时
  • 信道映射 与跳频
  • 接入地址、数据包-校验种子、第一发送窗口
连接建立后立即协商
  • 物理层（PHY）：LL_PHY_REQ/RSP；从连接请求的 PHY 开始
  • 数据包数据长度：LL_LENGTH_REQ / RSP
  • 属性协议最大传输单元（ATT MTU）：ATT_EXCHANGE_MTU_REQ / RSP
Core 6.0·第 6 卷，B 部分（链路层）

连接从广播开始。广播商在三个主要广播信道37、38和39上每个广播间隔发送一次可连接的ADV_IND数据包。扫描仪倾听；当它听到想要连接的 ADV_IND 时，它会在带有 CONNECT_IND 的数据包之后的同一信道上进行应答。从那时起，扫描仪就是一个 LE ACL 连接的中心设备，而广播商就是一个 LE ACL 连接的外围设备。对于扩展广播，辅助信道上的 AUX_ADV_IND、AUX_CONNECT_REQ 和 AUX_CONNECT_RSP 也会发生同样的情况。注意这句话：队列层在尝试连接时将扫描端称为发起端，与CS发起端无关。 CONNECT_IND 修复链路的时序和信道：连接间隔、外围设备延迟、监控超时、信道映射和跳频，以及接入地址、CRC 种子和第一个数据包的传输窗口。稍后可以通过连接参数更新来更改时间。 CONNECT_IND 中没有三件事；它们是在新链接形成后立即进行协商的。 PHY：链路在连接请求使用的 PHY 上开始，1M 具有传统广播或具有扩展广播的辅助广播 PHY，PHY 更新可以将其移动到 2M 或编码。托盘层数据长度，每个数据包的最大有效负载。还有 ATT MTU，它是 GATT 交换，而不是链路层交换。下一张幻灯片显示了时序参数如何随着时间的推移塑造连接；当我们调整测距数据时，谈判就会回来。该图是说明性的。

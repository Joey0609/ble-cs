One level up: a CS event groups the subevents that hang from one ACL anchor. Its first subevent starts the offset after the anchor; the Central fixed that offset in LL_CS_IND, inside the window proposed with LL_CS_REQ. The event holds Subevents_Per_Event subevents, 1 to 32, each starting one subevent interval after the start of the previous one, counted in 625 µs. Subevents do not overlap, so the interval is longer than the subevent length; with a single subevent per event it is zero. The whole event spans (number of subevents − 1) × subevent interval + subevent length, and it has to end before the next CS event, which starts the same offset after the anchor one event interval later, counted in connection intervals.

What a subevent boundary changes: each subevent is filled with the rules of the previous slides, so it opens with fresh mode-0 steps; the frequency estimate is only trusted within one subevent. What it does not change: the main/sub-mode sequence and the channel arrays belong to the procedure, so an unfinished block continues and the next channels follow on.
